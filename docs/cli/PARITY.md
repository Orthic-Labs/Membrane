# CLI parity

## Source of truth

The typed operation registry in `membrane-protocol` is the source of truth for operation IDs, help text, parameters, flag names, and defaults. The canonical operation index is `schemas/registry/operations/operations-index.v1.golden.json`.

A CLI subcommand name is the lowercased operation ID with dots replaced by dashes. Parameter names are exposed unchanged as long flags by prefixing them with `--`. The parser consumes the registry help text and defaults directly.

`install` and `uninstall` remain independent product-management subcommands. They are not operation-registry entries and are not removed or generated by the parity gate.

## Build gate

The `membrane` build script computes SHA-256 over the canonical compact JSON list of operation IDs. The generated parser snapshot contains the same digest on its `operation_registry_version` line.

Compilation fails when the registry digest and generated snapshot differ. The compile-time assertion in `dispatch.rs` also requires the generated banner and current digest line. Registry edits therefore cannot silently leave a stale CLI surface.

## Regenerating after registry edits

1. Update the canonical operation index and the typed `OPERATIONS` projection together.
2. Regenerate the parser snapshot from the typed registry:

```sh
cd engine
MEMBRANE_REGENERATE_CLI=1 cargo run -p membrane --bin cli-parity -- --generate > crates/membrane/src/generated_cli_subcommands.rs
```

3. Inspect the generated operation arms, flags, defaults, and help comments.
4. Run the parity report, then the focused build check:

```sh
cargo run -p membrane --bin cli-parity
cargo check -p membrane -p membrane-protocol
```

Do not hand-edit `generated_cli_subcommands.rs`. The fixed banner marks it as generated output.

## Drift report

The `cli-parity` binary prints one JSON object:

- `total_ops`: number of typed registry operations checked.
- `reachable`: number of registry operations found in the parser snapshot.
- `missing`: registry operations with no matching CLI subcommand.
- `extra`: parser subcommands with no matching registry operation. An entry prefixed with `registry:` indicates disagreement between the canonical JSON index and typed registry.
- `flag_drift`: triples containing the operation name, expected flag/default, and actual flag/default. Missing flags use `<missing>`; parser-only flags use `<none>`.

A drift-free report has equal `total_ops` and `reachable` values and empty `missing`, `extra`, and `flag_drift` arrays.

## Running the checker

From `engine/`:

```sh
cargo run -p membrane --bin cli-parity
```

The binary reads the canonical operation index, compares it with the hardcoded clap-derived snapshot, prints JSON to standard output, and exits 0 when drift-free. It exits 1 for any missing operation, extra subcommand, flag/default mismatch, unreadable index, or malformed index.
