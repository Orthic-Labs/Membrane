## P1 — Correctness (verified)

1. **Blueprint generation-mismatch guard is bypassable — stale reads accepted and cached.** When a provider response omits both `generation` and `result.generationId`, the fallback resolves `observed` to `query.expected_generation.clone()`, so the `observed != expected` guard can never fire; the stale result is cached keyed on `expected_generation`, poisoning subsequent callers for the TTL. Sole Blueprint-drift gate in this client. **Directly verified.** [blueprint_client.rs:627-647](engine/crates/membrane-federation/src/blueprint_client.rs:627)
2. **Federation merge silently drops a disagreeing provider's evidence** when the winner's own entries are self-consistent — no `conflict_omission`/warning emitted, so `is_partial()` can report `Complete` despite a real cross-provider conflict. Code-shape argument, not independently skeptic-verified. [merge.rs:196-242](engine/crates/membrane-federation/src/merge.rs:196)
3. **`is_version_demoted` conflates 0.0-freshness with superseded identity** — a legitimately-old candidate is hard-rejected (`superseded_version`) before ranking rather than down-ranked, so it can't backfill if the fresher proof was dropped earlier. [planner.rs:1054-1059](engine/crates/cortex-core/src/planner.rs:1054)

## P1 — Schema / contract drift (verified)

4. **`ContextPacketV1.reconciliation` is unenforced by the canonical JSON Schema — and CI can't catch it.** The Rust struct (MBR-608, 2026-08-21) and `docs/architecture.md` both treat `reconciliation` as an always-present receipt field, but `schemas/context-packet.v1.schema.json` (last touched 2026-08-08) omits it under `additionalProperties:false`. The round-trip test passes only because the golden fixture has no `reconciliation` key and the field is `Option`+`skip_serializing_if` — so a real packet carrying a reconciliation would **fail schema validation**. Byte-identical stale copy in `engine/crates/membrane-protocol/assets/schemas/`. **Directly verified.** Fix: regenerate/add the field to the schema and add a golden fixture that exercises it. [types.rs:463-466](engine/crates/membrane-protocol/src/types.rs:463)
5. **Cross-language mirror drift with dead sync anchors.** `SELF_LOADING_CLIENTS` is `["claude","claude_code","codex"]` in Rust but `["claude_code","codex"]` in JS (missing `"claude"`) — **directly verified**. Its "keep in sync with `engine/federation/providers/rules.py`" comment points at a file that doesn't exist, and that dead pointer appears in **3** places; a second dead pointer (`tools/lib/context_contracts.py`, also gone) sits in the same file. Nothing enforces parity, which is why it drifted. Fix: derive the JS list from the Rust constant (codegen/shared JSON), delete the dead comments. [rules.rs:23](engine/crates/membrane-federation/src/providers/rules.rs:23), [context-renderer-lib.cjs:14,34-36](mcp/context-renderer-lib.cjs:34)
6. **Blueprint IPC response is not version-checked client-side.** JS stamps and enforces `protocolVersion` both directions; the Rust `BlueprintWireResponse` struct has no `protocol_version` field, so a future daemon protocol bump passes through `parse_result` unvalidated. Both are v1 today — latent. [blueprint_client.rs:138-147](engine/crates/membrane-federation/src/blueprint_client.rs:138)

   Clean control checks: `FederationResponseV1`, observable-event kinds (Rust/JS/schema aligned), README "9 providers" and "17 tools" all match code; the generated-doc tier (`product.md`/`product-truth.md`/`architecture.md`) is **genuinely current** — `check-docs.mjs --check` was run live and passed.

## P1 — Data-safety / durability (verified)

7. **Delivery-ledger `persist()` fsyncs the file but not the directory** — while the sibling mutation-outbox two functions away does `fsyncDirectory` after its rename and checks the return. A crash after the fsync'd write but before the dir entry is durable can lose a "block already delivered" record; on restart `hydrate()` treats the block as never-delivered, silently degrading the content-dedup guarantee. Fix already exists in-file — just call it. [delivery-ledger-store.cjs:79-100](apps/membrane-hub/src-tauri/runtime/resources/host-adapters/delivery-ledger-store.cjs:79)
8. **Installation-identity write (A2) and telemetry-cursor write (A5) share the same missing-dir-fsync / in-place-truncate durability gaps** — both low blast radius (re-derivable / self-healing to 0), flagged for consistency with the temp+rename+dir-fsync pattern used correctly elsewhere. [installation_identity.rs:307-369](engine/crates/cortex-store/src/installation_identity.rs:307)

   Verified strong: Cortex durable memory/decisions use WAL + `IMMEDIATE` transactions (crash rolls back cleanly; `synchronous=NORMAL` is the named durability boundary); migrations are atomic+idempotent; Blueprint ledger DB correctly self-declares non-durable/rebuildable.

## P1 — Security (verified by lens)

9. **No secret-pattern redaction on the primary context-delivery path.** `blueprint/src/lib/redaction.mjs` (`redactForEgress`) is used only by Blueprint's own CLI/support-bundle surfaces. The Rust federation providers that actually stream file/rule bytes into the agent packet (`live_files.rs`, `rules.rs`) call no redaction; `normalize_overlay_path`'s denylist covers only `.agent/`/`.blueprint/` — `.env`, `id_rsa`, `*.pem`, `.aws/credentials` all pass its charset filter. Only the ScopeGrant allow-list stands between a secret path and the agent; no defense-in-depth if a bad/compromised grant includes one. Fix: port the redaction regexes into the federation candidate-construction point and/or add secret-filename denies. [live_files.rs:508-532](engine/crates/membrane-federation/src/providers/live_files.rs:508)

   Verified strong: ScopeGrant validation fail-closed (Ed25519, issuer/expiry/identity binding); path confinement canonicalize + symlink-recheck fail-closed; receipt integrity computed from actual rendered text; process spawn argv-based with `env_clear`+allow-list; MCP `authorize()` intersects authority (no escalation). No secrets in tree (matches are detector fixtures).

## P2 — Performance (verified)

10. **Recall path scans the whole corpus per query.** `recall_eligible_ids_on` materializes a `HashSet` of every eligible memory on every recall — no composite index over its `(authority, lifecycle_state, superseded_by, effective_from_ms)` predicate — just to filter a `limit*4` candidate set. O(corpus) per query, grows unbounded. Add the composite index. [store.rs:1688-1705](engine/crates/membrane-runtime/src/store.rs:1688)
11. **`effectiveness_history` is an unbounded `Vec` cloned per query** — appended on every task outcome with no cap/eviction, fully cloned twice per recall. Grows monotonically for process lifetime. [store.rs:1857,2933,4462](engine/crates/membrane-runtime/src/store.rs:1857)
12. **Blueprint `store-sqlite.mjs` deletes + reinserts the entire repo graph on every build**, including incremental builds of byte-identical files (12-table delete then per-row reinsert). One transaction (not N fsyncs), but O(full-graph) CPU+WAL per build regardless of what changed. No true delta-apply path. [store-sqlite.mjs:1106-1160](blueprint/src/graph/store-sqlite.mjs:1106)
13. **`mcp/server.mjs` spawns a fresh `node client.mjs` per packet call** (and per workspace repo target) — tens of ms of process-startup overhead per call, scaling with fan-out width. Correcting an earlier imprecise flag: the 9-provider fan-out itself is clean in-process async; the spawn is at the JS client boundary. Fix: persistent connector. [server.mjs:255-266,822,861](mcp/server.mjs:255)

   Verified clean: RRF fusion is O(n log n) not O(n²); `live_files`/`rules` are bounded to authorized paths (no full-repo walk); release profile (opt 3 / thin LTO / codegen-units 1) sound.
