# MBR-804 whole-task benchmark

This contract measures end-to-end task success, stale/unauthorized/missed-authoritative context, latency, token use, cache behavior, cost, and control outcomes. A receipt must name exact release (40-char commit, generation, client, service), corpus (version, case count, SHA-256), every model, and macOS/Windows hardware.

The bakeoff configuration, input corpus, and generated receipt are immutable and identified by SHA-256. Both host receipts must be current, measured, tied to same release generation, and carry their own hashes. Failures remain an explicit array; absence of failures is not evidence of success.

`verify-whole-task-benchmark.mjs` fails closed for missing, stale, unauthorized, mismatched, estimated, or incomplete evidence. `status: source-ready` describes this protocol only and can never produce PASS. Each metric carries `measured: true`; estimated values are not accepted. Publication requires explicit `disposition` (`not-published`, `internal-only`, or `published`) and boolean approval.

Run synthetic checks with `node --test tests/benchmarks/whole-task.test.mjs`. No benchmark is run by this source contract; no result is claimed here.

## Harness, corpus, and holdout protocol

The receipt contract above is the wire shape a whole-task benchmark result must satisfy. This section adds the harness that produces one, and the holdout protocol that keeps results from being tuned against the evaluation set.

### Corpus

`benchmarks/whole-task/corpus.fixture.json` is a synthetic, unmistakably labelled fixture (`"fixture": true`) covering task_success, unauthorized_context, stale_context, missed_authoritative, latency, tokens, cache, and cost scenarios. It exists to exercise the harness and holdout math at task-implementation time, never to stand in for a real measured product benchmark — the runner enforces this in code (below), not only in documentation. A real corpus for a Book-gate run is a separate file with its own `id`/`version`/`sha256` and no `fixture: true` marker.

### Holdout protocol (`benchmarks/whole-task/holdout.mjs`)

The split between cases that may be inspected while tuning the product ("visible") and cases that are only ever scored ("holdout") is a pure, deterministic function of `(case id, salt)`: each case ID is hashed with the salt (`sha256(salt:caseId)`) and bucketed by the resulting fraction against `holdoutFraction`. Anyone holding the corpus and the salt can recompute the exact same split — `assignment` is never asserted, only derived — and `verifySplit()` recomputes it and fails closed on any mismatch (wrong salt, tampered assignment, tampered hash).

To stop the holdout boundary itself from being chosen or adjusted after seeing how a run performed, the protocol uses commit-reveal: `commitSalt(salt)` (its sha256) is published *before* a run starts; the plaintext salt stays private until results are locked, then is revealed and checked against the pre-published commitment. A receipt whose revealed salt does not match its own pre-committed commitment is reported `invalid`, not `complete` — see `runWholeTaskBenchmark`'s salt-commitment check in `benchmarks/whole-task/runner.mjs`.

### Vector-bakeoff consumption, never rerun (`benchmarks/whole-task/bakeoff-reference.mjs`)

`K5`/`G7` require this task to consume the already-completed vector-backend bakeoff (MBR-509 lineage: `docs/plans/2026-08-01-vector-backend-bakeoff-harness.md`, `docs/benchmarks/vector-backend/2026-08-02-rust-vector-optimization-bakeoff-2-report.md`) rather than rerun it. `bakeoff-reference.mjs` pins the sha256 of five existing, immutable artifacts at authoring time — the bakeoff config (`engine/vector-bakeoff/config/round1-v1.json`), its fixture input manifest (`engine/vector-bakeoff/fixtures/smoke-v1.manifest.json`), the final cross-host decision report, and both pre-existing per-host bakeoff receipts (`docs/benchmarks/vector-backend/round1/{mac,windows}/receipt.json`) — and `verifyBakeoffReference()` recomputes those hashes from disk on every call, failing closed (`mutated`/`missing`) if any artifact has drifted, been deleted, or been regenerated by a rerun. It also cross-checks that both host receipts agree on `configSha256`/`inputDigest`/`manifestSha256`/`gitHead`, proving both hosts measured the identical, un-rerun input. No cargo, Python harness, or other process is ever spawned by this module — it only reads and hashes files already on disk.

### Runner (`benchmarks/whole-task/runner.mjs`) and CLI (`scripts/qualification/benchmark/run-whole-task-benchmark.mjs`)

`runWholeTaskBenchmark({ corpusPath, salt, holdoutCommitment, release, models, hardware, hostReceiptPaths, execute })` wires the corpus, the holdout protocol, the bakeoff reference, and a caller-supplied per-case `execute` function (this repo's harness never drives a client/model itself) into a receipt matching the contract above, then validates that receipt with the existing, unmodified `verify-whole-task-benchmark.mjs` before reporting `status: 'ran'`. Every real-execution precondition degrades explicitly instead of fabricating a result:

- no executor configured → `degraded: executor-not-configured`
- corpus missing → `degraded: corpus-not-found`
- salt/commitment missing → `degraded: holdout-not-configured`
- revealed salt does not match its commitment → `invalid`
- bakeoff reference artifacts missing or mutated → `degraded: bakeoff-reference-unavailable`
- a non-fixture corpus without both `hostReceiptPaths` (macOS and Windows) → `degraded: host-receipts-not-configured`

`writeHostReceipt({ evidenceRoot, platform, releaseGeneration, measured })` records this harness's own per-platform receipt (real hostname/arch via `node:os`/`process.arch`, a caller-asserted `measured` flag, the release generation) — the "both host receipts" the acceptance criterion requires for MBR-804's own run, structurally the same shape as MBR-801's `evidence/qualification/mbr801/{macos,windows}/receipt.json`. A corpus with `fixture: true` (including the default corpus above) is hard-guarded in code to status `source-ready` regardless of executor output, so a protocol self-test can never be reported as `complete`/passing evidence.

The CLI (`scripts/qualification/benchmark/run-whole-task-benchmark.mjs`) exposes every option as a flag for manual, Book-gate-time invocation; it supplies no `execute` default and performs no build, download, or network call. Run its own wiring tests with `node --test scripts/qualification/benchmark/run-whole-task-benchmark.test.mjs`, and the harness/holdout/bakeoff tests with `node --test benchmarks/whole-task/holdout.test.mjs benchmarks/whole-task/bakeoff-reference.test.mjs benchmarks/whole-task/runner.test.mjs`.
