- `engine/crates/membrane-mcp/src/tools.rs`
  - `push` inputSchema: removed `keywords` and `lifecycle` — the Cortex
    admission route (`agent_memory_push`) accepts neither, so advertising them
    silently discarded agent intent. With `additionalProperties:false` the
    fields (and any non-memory `destination`) now fail closed with
    `memory_envelope_invalid` instead of being accepted and dropped.
    Verified live: the pre-change installed build accepted
    `keywords`/`lifecycle` and stored only the body.
  - Added test `public_push_rejects_fields_the_executor_does_not_honor`
    asserting `destination`, `keywords`, `lifecycle` each fail validation
    while the minimal valid push still validates.

- `engine/crates/membrane-runtime/src/memory_sentinel_producer.rs`
  - Added `sentinel_dimensions(conn, now_ms)` producing a `dimensions` map of
    the nine MEM-029 health dimensions the DB can observe (duplication,
    relationIntegrity, isolation, provenanceGaps, lifecycleAnomaly,
    projectionDrift, observedRecall, crowding, reviewBacklog).
  - Each dimension is an independent probe (`probe_ids`/`probe_scalar` →
    `dimension`) that returns `observed{count,ids,reason}` on a successful
    read and `not_evaluated{reason}` on failure — one unavailable source never
    masks the others and never fabricates a zero. `ids` bounded by
    `MAX_ITEMS`, content-free. Wired into `build_sentinel_report_from`.

- `engine/crates/membrane-runtime/src/memory_sentinel_view.rs`
  - Added `SentinelDimension{state,count,ids,reason}` and an additive
    `dimensions: BTreeMap<String,SentinelDimension>` on `MemorySentinelView`
    (`skip_serializing_if` empty → absent on pre-change reports, never
    fabricated). Projection in `project()` bounds each list to `MAX_ITEMS`.
  - Added tests `absent_dimensions_stay_absent_in_the_projection` and
    `observed_and_unavailable_dimensions_project_distinctly`.
