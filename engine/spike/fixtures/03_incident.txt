The on-call investigation began at 02:14 UTC when the alerting system fired on a sustained increase in p99 latency for the recommendation service. Initial triage pointed at the new embedding worker, which had been promoted to production the previous afternoon. The worker itself was healthy and serving traffic, but downstream consumers were reporting that a non-trivial fraction of requests were returning empty vectors.

A first look at the worker logs showed a large number of tokenizer warnings. The warnings themselves were not new, but their volume had increased roughly nine-fold since the promotion. Closer inspection revealed that the warnings were clustering on inputs longer than 512 tokens, which is the model's documented maximum. The previous code path was silently truncating long inputs; the new code path was forwarding them through unchanged, which caused the tokenizer to emit the warnings and the model to produce undefined behavior on the padded output.

The fix was a one-line guard in the request handler that rejects any input above 480 tokens with a structured error so the caller knows to chunk before retrying. The guard was rolled out at 03:02 UTC and the latency alerts cleared within four minutes. A follow-up was filed to add an automated load test that exercises long inputs so this regression cannot recur without a test failure.

The postmortem action items are tracked in the engineering tracker under the October on-call rotation. The owner for the load test work is the platform team; the owner for the input validation contract change is the API team. The full timeline, including the dashboard snapshot at the moment of mitigation, is attached to the incident record.
