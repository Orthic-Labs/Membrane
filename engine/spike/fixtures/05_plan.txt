The unification work moves the deterministic context-engineering layers from a mix of Python and Node scripts into a single Rust crate. The motivation is straightforward: maintaining two divergent implementations of the same logic is a slow leak, both in correctness and in onboarding. Once the engine is unified, the desktop application, the workspace tooling, and any future consumer can call the same Rust code through a stable CLI and HTTP contract, and the Python and Node scripts can be retired.

The scope of the unification is deliberately narrow. It includes only the layers that are pure deterministic transforms over text: command execution with bounded output, code skeletonization, prose compression, and the routing layer that dispatches an input to the right transform based on its type and size. It explicitly excludes anything that requires an LLM call, anything that is a policy string rather than mechanism, and anything that is tightly coupled to a specific consumer's prompt format.

The riskiest assumption in the plan is that the learned prose compressor can be exported to ONNX and executed through the runtime that the crate already uses for sentence embeddings, without a measurable quality regression. The mitigation is a spike before any production implementation: export the model, run it side by side with the reference Python implementation on a small set of fixtures, and only proceed with the full implementation if the retained-token Jaccard between the two outputs meets a defined threshold. If the threshold is not met, a deterministic heuristic fallback ships as the first version and the learned path is deferred.
